# Implementation plans

One markdown file per ticket / unit of work, named for the issue it implements (e.g.
`42-offline-guidance-cache.md`). The agent drafts the plan here; **a human approves it
before any code is written** (see `../dev-workflow.md`, step 2).

A plan is the thing that gets reviewed -- it's diffable, referenceable, and outlives
any single agent session. Keep approved plans in the repo so the PR can reference
them and reviewers can check the diff against the plan that was agreed.
